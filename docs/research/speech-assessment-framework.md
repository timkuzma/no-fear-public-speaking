# Evidence-based speech assessment for No Fear Stage

Research date: 13 October 2026. This document is an implementation specification proposal, not a claim that the proposed assessment has been validated or deployed. Technical prose is English; illustrative product feedback is Russian. All examples are invented test fixtures, not recordings of users.

## Decision

Use a purpose-sensitive, evidence-grounded coaching framework. The product should help a speaker understand what worked and make one useful change in the next recording. A universal method means stable rules for interpreting evidence and adapting to the speech; it does not mean the same required content, structure or score for every genre. Keep the one-minute starter free of mandatory topic, audience or content checklists.

Separate three decisions: whether the material can be assessed; which observation the material supports; and which next action is useful. Exact transcript provenance answers only the second decision's source-existence component. It does not establish semantic correctness, complete coverage, factual truth or the coaching value of the observation.

## Evidence-derived conclusions and product proposals

Evidence: established assessment instruments condition content and language on a particular speaking event (S1–S3); the full presentation rubric is not a short-answer rubric (S1); guide-specific advice can conflict across legitimate formats (S5–S7). Proposal: use genre and purpose as provisional interpretation context, evaluate answers separately, and express only supported observations.

Evidence: useful feedback connects work to an actionable continuation and does not rely on judgments of the person (S4, S8, S9). Proposal: show one prioritized next practice, preserve one or two useful strengths and explain the reason for the change. This is a design hypothesis to validate with users, not a promised educational effect or compulsory feedback sandwich.

Evidence: transcript errors, hallucinations and domain/group variation are real risks (S10–S14). Proposal: distinguish transcript-derived findings from audio-derived measurements, test Russian material across conditions, and refuse unsupported acoustic or psychological judgments.

## Current implementation: verified facts and gaps

Inspected owners: `server/ai.py`, `docs/llm.md`, `docs/api-contract.md`, and relevant assertions in `tests/test_ai.py`.

The maintained module sends normalized audio to ASR, then text to the chat model. `DATA_RULE` already prohibits invented numbers, personality/emotion/voice/gesture judgments, obligatory project-defense structure and topic-as-evidence. `analyze` accepts one speech plus up to three answers, can include each answer's persisted question, and excludes question text from transcript evidence and word counts. The server creates canonical exact quote IDs and user criterion IDs; it checks membership, source segment and criterion coverage. Criteria are optional; when absent the server publishes an empty criterion list. Duration, word count and average recording rate are computed locally.

The following are **observed validation gaps**, not demonstrated production failures:

| Gap in current code | Consequence | Proposed material/change |
| --- | --- | --- |
| `insight` is checked only as a bounded nonempty string | An invented or irrelevant rewrite may pass although every other finding has a valid quote | Specify a structured internal next-practice action with a link to a validated finding; derive the current public insight from it |
| Quote membership establishes provenance, not entailment | A real sentence may be used to support a contradictory interpretation | Label positive/negative entailment fixtures and require a semantic audit in evaluation; decide whether a runtime critic adds measured value |
| The schema permits a non-unknown user criterion with any valid quote | “Уверенность” or “Жесты” may receive a status despite unavailable evidence | Maintain a capability contract and refusal fixtures; preserve the requested label with `unknown` and explain the relevant missing modality |
| `_findings` requires 1–5 strengths and 1–5 recommendations; prompt asks 1–3 | Sparse material encourages forced praise or artificial deficiencies | Specify honest insufficient-material behavior and zero-length lists where necessary; version schema and UI if implementing |
| A single quote may be used for a whole-speech absence claim | “Вы не объяснили причину” can be unsupported even if an excerpt exists | Require complete coverage for absence claims and represent internal evidence scope separately from excerpt provenance |
| Report metrics aggregate speech and answers | Changes to answer duration can resemble a change in main-speech delivery | Keep aggregate descriptions accurate; decide whether per-speech descriptive metadata is useful before adding fields |

No runtime changes are made by this research. Existing mocked tests prove useful structural guarantees, not live model quality or speech-assessment validity.

## Context contract without a longer setup flow

Keep starter topic/criteria empty. Infer only a tentative working purpose from the recording: explaining something, proposing a decision, recounting an event, thanking someone, introducing oneself or answering a question. If the inference is weak, give local text feedback without a genre diagnosis. Never require the speaker to fill missing context merely to receive feedback.

Use explicit user purpose/audience where the user voluntarily supplied it; such input informs relevance but cannot prove the speech said something. A legacy `scenario="defense"` is weak interface context, not permission to impose market size, financial results or a project template. `topic` remains history metadata/context. Do not invent expertise, audience knowledge, decision authority, time limits or intended outcomes. Internal contextual inference is not a new formal criterion.

Suggested internal context fields, only if supported and actually needed: `purpose_hypothesis`, `genre_hypothesis`, `context_basis` (user-declared or transcript-inferred) and `context_uncertain`. These stay out of the simple report by default. Do not expose numeric confidence from the model as a calibrated probability.

## Contextual diagnostic rubric

This is a proposed internal coaching lens, **not a compulsory scorecard**. Formal criterion statuses appear only for explicitly selected user criteria. The engine can suggest helpful changes without telling users that every speech must satisfy every row.

| Lens | Transcript-observable success | Evidence of a useful improvement | Adaptation / abstention |
| --- | --- | --- | --- |
| Communicative point | A listener can identify the main idea, wish, explanation, gratitude or request from what was said | Two incompatible takeaways, an undefined referent or the actual request left unclear | A toast can have a shared sentiment; a story may reveal its meaning at the end. Do not demand a thesis in the first sentence |
| Coherence and organization | Adjacent ideas connect; sequencing fits the task | Unexplained jump, ambiguous chronology, a conclusion that contradicts its premise | Chronology, comparison, problem–solution and narrative arc are alternatives. A direct short answer needs no formal introduction/conclusion |
| Clarity of expression | A term, reference or sentence has enough context for the intended listener | “Это”, “так”, “эффективно” or unexplained jargon obscures the specific meaning | Technical language is acceptable for experts; ASR punctuation alone is not evidence of poor sentence construction |
| Support and reasoning | Reasons/examples are connected to the claim where the purpose requires justification | A stated conclusion does not follow from the stated premise, or a promised example does not explain the point | Personal memories and ceremonial remarks need no statistics; do not prescribe invented examples or numbers |
| Audience fit | Declared listener needs are addressed in wording or explanation | A novice-facing explanation relies on an undefined necessary term | Audience unknown: no categorical mismatch finding. Simulated audience animation supplies no reaction evidence |
| Precision and uncertainty | A limitation, condition or source status is expressed where needed | Universal certainty from limited evidence, contradiction or unclear measurement basis | “Research says” is reported attribution, not verification. Separate explaining a claim from validating external truth |
| Ending and intended continuation | The final meaning/action suits the communicative purpose | A proposal names a problem but leaves its requested decision genuinely unclear | No universal call to action; a toast, story and informative answer may end differently |
| Relevance of a Q&A answer | The answer addresses the persisted question's specific request | Repeating a benefit when asked about cost; supplying a related fact without the requested explanation | Missing question: cannot assess responsiveness. Legitimate uncertainty, correction, premise rejection or request for clarification can be effective answers |
| Economy | Repetition serves emphasis, explanation or emotional meaning | Repeated wording prevents the listener from seeing a distinction or the main point | Never classify all repetitions as flaws or measure concision by arbitrary word limits. ASR duplication may be a transcription defect |

For a selected criterion, interpret `met`, `partial`, `not_met`, `unknown` against a written anchor specific enough for independent reviewers. `unknown` means insufficient/unavailable evidence; it is not a bad performance. For “Назвать причину переноса и новый срок”, a stated cause plus a new date supports `met`, a cause without a new date supports `partial`, neither component in a complete reliable recording may support `not_met`, and an incomplete/unreliable transcript supports `unknown`. A bare acknowledgment that a delay occurred does not establish its cause. Review borderline and compound criteria rather than relying on the model's intuition; retain the user's label even if internal assessment separates its observable components.

Do not introduce a global percentage, star rating, “confidence score”, population percentile or a before/after grade. If numeric scoring later becomes a user need, separately establish construct validity, anchors, inter-rater agreement, subgroup behavior, uncertainty and meaningful change thresholds. Human rubric validation does not automatically transfer to an LLM. The current product goal can be served by descriptive coaching without scores.

## Observability matrix

| Claim or measurement | Current available evidence | Allowed report behavior | Needed for any future claim |
| --- | --- | --- | --- |
| Content, wording, local reasoning | Recognized text plus canonical spans | Explain what the transcript says, with a relevant quote | Human checks of semantic correctness and ASR defects |
| Whole-speech omission | Complete speech text, known capture completeness | Carefully scoped “в этой записи…” only when coverage is adequate | Coverage metadata and absence-claim labels; one excerpt does not prove absence |
| Response relevance | Answer text plus persisted matching question | Assess that pair; quote the answer, not the question as user speech | Stable pair binding; no generated replacement question |
| Speaker's factual claim | Statement/source attribution in transcript | “Вы называете…”; ask for a source or distinguish observation from inference | External research/reference evidence, with a separate verification workflow |
| Duration | Locally measured decoded duration | Recording duration, with clearly stated aggregation | Preserve measurement method; distinguish requested timer and actual capture |
| Recognized words per minute | Recognized words / recording duration | Descriptive average including silence and ASR errors | Cannot become articulation rate without speech interval detection and validation |
| Fillers, hesitations, pauses | ASR text may omit/edit them; no validated timing | Do not report their acoustic frequency or timing | Manually labeled audio, timing and validated detection for Russian conditions |
| Loudness, pitch, intonation, articulation | Audio exists, but analysis model receives text and current code has no such validated features | Abstain | Separate acoustic pipeline, device-aware normalization and human-validity study |
| Eye contact, gestures, posture, slide design | Optional private video is retained, not analyzed | Abstain | Explicitly supported visual/slides pipeline and adequate privacy/validation |
| Confidence, emotion, anxiety, honesty, personality | No valid direct measure | No psychological or personal labels | Not supported by the pilot; user self-report is not an inferred diagnosis |
| Audience understanding, persuasion, interest | Synthetic questions/audience; no real reaction data | Describe possible listener interpretation as a hypothesis | Actual listener measures and a task-specific study |
| Skill improvement | Two task attempts may differ in topic, material and conditions | Describe a specific supported change when comparable | Same target skill, comparable task evidence, test/retest error and longitudinal human checks |

## Feedback construction and examples

Proposed internal chain: **source observation → likely communication consequence → one action → a faithful sample or scaffold → a check for the next attempt**. A claim about the likely listener experience must be phrased as an interpretation, not a measured fact. Each report item should work on its own. Choose the most consequential supported change; avoid duplicating the same recommendation under multiple titles.

Sample rewrites may rearrange known facts. New specifics must be visible placeholders or a request to the speaker, never invented achievements, costs, names or causal explanations. Keep the original quote distinct from the rewrite. If evidence is too thin, say what can be understood and offer a small clarification task; do not manufacture flaws to fill a template.

| Synthetic fixture / purpose | Grounded feedback and next practice | Forbidden substitution |
| --- | --- | --- |
| Explanation: “Кэш хранит результат. Если запрос повторится, система возьмёт его оттуда.” | Strength: “Вы связали термин с его действием: повторный запрос использует сохранённый результат.” If intended novice audience is declared, next practice can ask to replace “оттуда” with “из кэша”. Check that the repeated-query explanation remains clear | “Вы уверенно объясняете”, or inventing a speedup of 40% |
| Proposal: “Предлагаю открыть библиотеку рядом со школой. Там ученики смогут вместе готовиться к урокам.” | “Сохраните связь места и пользы. В следующей попытке назовите, какой шаг вы предлагаете слушателям: обсудить помещение или поддержать идею. Выберите тот вариант, который соответствует вашей реальной цели.” Choice is a scaffold, not a claim of an existing plan | Mandatory business model, budget calculation or market size just because `scenario=defense` |
| Personal story: “Я заблудился в новом районе. Сосед показал дорогу. Теперь я сам помогаю тем, кто ищет дом.” | Strength: “Финал связан с тем, что произошло в начале.” Next challenge: retell this same turn more distinctly: “Сосед помог мне, и теперь я помогаю другим.” Check that the past help and present action remain linked | Missing statistics, “not enough proof”, compulsory problem–solution slide |
| Toast: “Спасибо, что были рядом, когда всё менялось. Пусть впереди у нас будет больше спокойных вечеров вместе.” | “Вы связали благодарность с общим пожеланием.” If a next challenge is appropriate: “Сохраните эту связь; попробуйте уточнить, какую помощь вы хотите отметить, только если готовы поделиться реальным эпизодом.” No invented deficiency | Requiring an argument, cost estimate, quantified result, or interpreting sadness/anxiety |
| Introduction: “Я дизайнер. Делаю интерфейсы для сервисов записи к врачу. Ищу команду, где смогу заниматься доступностью.” | “Вы объяснили сферу работы и цель знакомства.” Next practice can make a relevant term accessible: “Интересует работа над тем, чтобы сервисом было удобно пользоваться людям с разными возможностями.” Treat this as a possible wording, not a stronger credential | Inventing awards, years of experience or successful outcomes |
| Q&A: question “Почему запуск перенесли?”, answer “Сервис будет полезен команде. Мы хорошо его подготовим.” | “Вы назвали пользу, но в этом ответе не объяснили перенос. В следующей попытке начните с реальной причины: «Запуск перенесли, потому что [причина]»; затем скажите, что это меняет.” Check the first sentence answers “почему” | Supplying an invented shortage of developers; judging a whole presentation by this short answer |
| Q&A honest uncertainty: question “Сколько стоит запуск?”, answer “Стоимость пока не рассчитана. Сначала нужно уточнить объём работы.” | “Вы обозначили границу знания и следующий шаг расчёта.” A useful refinement may ask who will calculate or when, if that is actually known | Downgrading every “не знаю” or fabricating the price |
| Sparse speech / uncertain ASR: “Эта штука… ну… работает как-то.” | “По этой расшифровке можно понять, что вы описываете работу чего-то, но предмет не назван. Повторите одну фразу: что это и что оно делает.” If recognizer integrity is suspect, invite playback/retry instead of judging the speech | Mandatory three strengths, diagnoses of nervousness, counting the printed ellipses as measured pauses |

The concise product presentation should expose the chosen action, what already helps and the relevant evidence. The matrices, capability rules and evaluation labels belong in internal specification and testing; they are not additional mandatory UI panels.

## Dataset and annotation materials

Proposed initial corpus: **72 base recordings/transcripts**, covering six purpose groups (explanation, proposal/persuasion, story, ceremonial/gratitude, introduction and free reflection), each with four evidence conditions (clear, ambiguous, sparse and materially inconsistent), three examples per condition. Add **24 Q&A pairs** covering direct, partial, irrelevant, honest-uncertain, correction/premise-rejection and clarification answers. Add **24 boundary fixtures** for ASR/injection/ownership-of-context failures. These are planning quantities, not a power calculation or proof of statistical adequacy; expand weak slices before making broad claims.

The consolidated plan selects 40 development / 20 judge-calibration / 60 locked acceptance scenarios, partitioned by speaker/source/task family. The 72+24+24 numbers above describe a coverage proposal, not an alternative data split; refine coverage within the selected partitions without leaking related variants.

Use real permissioned Russian recordings for end-to-end ASR validation; text-only or TTS fixtures are sufficient for deterministic software paths but cannot establish typical-user acoustic quality. Public corpora such as Golos/OpenSTT are optional supplemental ASR checks, not substitutes for spontaneous product recordings. Confirm each dataset's actual license and permission constraints before copying or redistributing; do not assume a paper's openness licenses all underlying audio.

For each case store fixture ID, purpose/context supplied, original transcript, ASR transcript if present, segment/question binding, capture completeness, criterion labels if selected, capability restrictions, acceptable observations, prohibited claims and acceptable next actions. Keep sources and private recordings outside public application assets. Link report evidence by span/ID; retain de-identified evaluation output separately from operational content-free telemetry.

Two independent Russian-speaking reviewers should label the same hidden evaluation cases, then adjudicate disagreements. At least one reviewer should have relevant speech/coaching experience; both use the written anchors and current observability contract. Reviewers see exactly the evidence the evaluated component sees. An ASR reviewer may hear the audio to create the reference transcript; a text-report evaluator cannot silently use unheard audio to label the model's inference as correct. Separate gold transcript, ASR output and downstream report quality.

Split by speaker and speech/task family where feasible; related paraphrases and repeated attempts stay in one partition to avoid leakage. Keep a frozen holdout apart from prompt development. Mix expert and novice vocabulary, Russian names/numerals, colloquial speech, legitimate repetitions, spontaneous corrections, code-switching, microphone/device conditions and noise. Recruitment metadata such as accent or accessibility needs must be voluntary; never infer nationality, diagnosis or ethnicity. Ensure there are known “good as recorded” cases so the engine learns that an improvement is not always a defect.

Review labels: source provenance, semantic support, context relevance, actionable next step, rewrite fidelity, respectful task focus, unsupported modality inference, invented facts, whole-speech coverage and Q&A binding. Accept multiple legitimate phrasings/actions. Exact-match prose grading would reward templates rather than utility. Evaluate changes with paired human preferences and structured error labels, not the model's explanation of its own excellence.

## Acceptance checks and implementation sequence

Proposed checks below are future gates, not checks already passed:

1. **Capability and scope.** Empty selected criteria always produces an empty formal criterion list. A selected gesture/voice/psychological criterion remains `unknown` with the current pipeline. Changing only history topic or interface scenario must not invent requirements or alter what evidence was said. A toast is not penalized for missing statistics or a call to action.
2. **Evidence semantics.** Verified quote IDs survive server substitution unchanged. A quote saying “не рассчитали стоимость” must not support “вы назвали стоимость”. An excerpt cannot establish absence elsewhere. Rewrites add no unsupported quantities/credentials/events. The priority insight has traceable provenance and does not contradict its source finding.
3. **Answers.** The relevant question is bound to its persisted answer index. Question words never become evidence or recognized word count. Missing questions trigger no responsiveness verdict. Honest uncertainty and premise correction can receive useful feedback. Three generated questions do not become three measured audience reactions.
4. **ASR robustness.** Separate silent/noisy audio, repetitions, interrupted sentences, negation, names and numbers. A recognizer hallucination must not be treated as speaker intent simply because it is a canonical quote. Compare human versus ASR transcripts for semantic fact/negation preservation and downstream report drift; label suspected-error cases rather than using a universal WER cutoff.
5. **Usefulness.** Reviewers can identify the next action, locate why it was suggested and judge whether it can be tried immediately. Recommendations remain focused and nonduplicate. A case with thin evidence yields an honest limited report, not fabricated praise or a project template.
6. **Repetition and fairness.** Re-run a representative subset with changed ordering/paraphrase and multiple bounded model runs. Review which errors concentrate by genre, device or voluntary speech-condition slice. Counts and uncertainty must accompany measured rates; small samples cannot certify broad fairness.

Initial hard invariants can require zero observed fabricated quotes, invented rewrite facts, unsupported psychological/visual/acoustic judgments and cross-answer evidence errors in the frozen acceptance suite. This is zero observed failures in a bounded corpus, not a zero-risk promise. Soft targets for actionability, relevance and faithfulness must be set after the baseline and human agreement are measured; do not choose impressive percentages without an error budget or denominator.
